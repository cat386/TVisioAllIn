# Дополнения из tvision-rs

Сравнение выполнено с локальными исходниками [cat386/tvision-rs](https://github.com/cat386/tvision-rs). Это реализация возможностей на C++14: Rust, Cargo, serde и дополнительные системные библиотеки для сборки не требуются. Классический API и стандартная палитра `TApplication` сохранены. Дополнения подключаются через `<tvision/modern.h>` и находятся в `namespace tvision`.

Снимок tvision-rs: `17d8bddbc84ae19aec9863601ffa0805669beb4b`.

## Что добавлено

| Область | TVisioAllIn до изменений | Реализация после сравнения |
|---|---|---|
| Темы | Классические BIOS-палитры; уже имелись 256 цветов и RGB | `Theme::Classic`, `Gruvbox`, `Twilight`, 135 элементов палитры; переключение и перерисовка во время работы |
| Выбор цвета | Классический редактор палитры | Сетка всех 256 цветов, клавиатура и мышь, модальный `TColor256Dialog`, контраст подписи |
| Таблица | Списки и собственная отрисовка приложениями | `TTable`, модели данных, заголовки, сортировка, закреплённые и скрытые столбцы, ширина и выравнивание, выделение, редактирование, буфер обмена |
| Дерево | Классический outline | `TTreeView`, узлы с данными, отложенная загрузка, поиск, флажки и промежуточное состояние родителей |
| Прогресс | Реализация на стороне приложения | `TProgressBar`: блоки, дробные Unicode-блоки, текст, произвольный знаковый 64-битный диапазон, неопределённый прогресс |
| Ввод | `TInputLine` и валидаторы | `TInputLong` со знаковым 64-битным диапазоном и `$`-hex; `TCombo` со списком выбора |
| Данные | Потоковая сериализация объектов Turbo Vision | Табличные модели, CSV, JSON, точное хранение чисел, типизированное редактирование, уведомления о прогрессе и отмена разбора |
| Файловые панели | Диалоги открытия файлов | `FilePanelModel`, `TFilePanel`, `TDualPanel`: каталог, фильтры, скрытые файлы, отметки, вкладки, цвета типов файлов |
| Примеры | Классические демонстрации | Ещё 10 целей: `themes`, `colors256`, `table`, `treeview`, `progress`, `json_table`, `json_load`, `json_parse`, `filemanager`, `data_demo` |

Gruvbox использует соответствие цветов палитры из tvision-rs; ссылка и MIT-атрибуция находятся в `source/modern/themes.cpp`. Twilight использует палитру DUSK. На терминале без 256 цветов приложение выбирает ближайшие BIOS-цвета. Поддержка RGB из исходной библиотеки также доступна.

Это не полная копия всех приложений tvision-rs: файловые панели не выполняют копирование, удаление и запуск файлов; `cmFileOpen` передаёт выбор приложению. Локализация всех классических диалогов, командная оболочка файлового менеджера и Rust-специфичные API не перенесены. Таблица изменяет ширину через API или Ctrl+стрелки; перетаскивание границ мышью не реализовано.

## Сборка и запуск

```sh
cmake -S . -B build -DTV_BUILD_EXAMPLES=ON -DTV_BUILD_TESTS=ON
cmake --build build --config Release --parallel
```

Исполняемые файлы находятся в каталоге сборки, для Visual Studio — в `build/Release`. Примеры `json_table`, `json_load`, `json_parse` принимают путь к JSON первым аргументом; `filemanager` — каталог. Без аргумента используются встроенные данные или текущий каталог.

```sh
build/json_table examples/modern/books.json
build/json_load examples/modern/books.json
build/json_parse examples/modern/books.json
build/filemanager .
build/table --smoke
```

Все 10 примеров поддерживают `--smoke`, который проверяет модели без открытия терминального интерфейса. При `TV_BUILD_TESTS=ON` эти проверки запускаются после сборки примеров. Проверки библиотеки используют встроенный тестовый фреймворк; для тестовой цели нужен C++17, для самой библиотеки — C++14.

Общие клавиши примеров: F6 меняет тему, F7 открывает палитру, Alt+X завершает работу. F4 выполняет действие текущего примера; F8 — дополнительное действие. В `json_parse` F4 форматирует JSON и показывает место ошибки, F5 сохраняет переданный файл. В табличных примерах F5 экспортирует CSV в `tvisio-export.csv` с подтверждением перезаписи. Ограничения примеров: входной файл до 128 MiB, экспорт до 100 000 строк.

## Темы

```cpp
#include <tvision/modern.h>

class App : public tvision::TThemedApplication {
public:
    App() : TProgInit(&TApplication::initStatusLine,
                     &TApplication::initMenuBar,
                     &TApplication::initDeskTop) {
        setTheme(tvision::Theme::Twilight);
    }
};
```

`TProgInit` — виртуальная база Turbo Vision: её инициализирует самый производный класс. `TThemedApplication` по умолчанию выбирает Gruvbox. Для собственного `TApplication` можно использовать `ThemePalette` и переопределить `getPalette()`. Метод `TModernView::setColors` задаёт индивидуальные цвета виджета, `usePalette()` возвращает наследование палитры владельца.

## Таблица и модели

```cpp
using namespace tvision;
auto model = std::make_shared<VecTableModel>(
    std::vector<std::string>{"Name", "Count"},
    std::vector<std::vector<std::string>>{{"Widgets", "12"}, {"Tables", "2"}});
model->setEditable(true);
auto *table = new TTable(TRect(1, 1, 60, 15), model);
table->rowNumbers = true;
table->multiSelect = true;
table->frozenColumns = 1;
window->insert(table);
```

Стрелки/PageUp/PageDown перемещают курсор, Ctrl+Home/End — к началу/концу данных, щелчок по заголовку сортирует. F2 или ввод текста начинает редактирование, Enter подтверждает, Esc отменяет. Ctrl+Left/Right меняет ширину столбца. Space переключает выделение строки, Shift+стрелки выделяет диапазон, Ctrl+A выделяет всё. Ctrl+C/Ctrl+Insert копирует ячейку или выделенные строки в TSV. Выделение хранится как индексы строк и сбрасывается после сортировки.

Для больших наборов используйте `FnTableModel`: таблица запрашивает только ячейки видимой области. Пример `table` показывает миллион вычисляемых строк без выделения памяти под миллион записей. Сортировка и редактирование доступны, только если модель их реализует. Изменения модели и обращения к виджетам выполняйте в потоке интерфейса; после замены структуры данных вызовите `setModel`.

`naturalCompare` сравнивает большие десятичные числа без преобразования в `double`, поддерживает экспоненту и естественный порядок `file2 < file10`. Числа сортируются перед текстом; сравнение текста без учёта регистра ограничено ASCII. Методы моделей можно использовать отдельно от интерфейса.

## JSON и CSV

```cpp
auto json = tvision::parseJson(text, [](size_t done, size_t total) {
    // Передавайте прогресс в основной поток. false отменяет разбор.
    return true;
});
auto model = std::make_shared<tvision::JsonTableModel>(std::move(json));
model->setEditable(true);
std::string saved = tvision::writeJson(model->data(), true);

auto rows = tvision::parseCsv(csvText, ';');
std::string csv = tvision::writeCsv(rows, ';');
```

JSON-модель принимает массив объектов, объединяет ключи в столбцы с сохранением порядка первого появления. Числа сохраняют исходное десятичное представление, включая значения больше 2^53. Редактирование существующей ячейки сохраняет её тип; для массивов и объектов вводится JSON. Парсер проверяет UTF-8, escape-последовательности и суррогатные пары, отклоняет повторяющиеся ключи, ограничивает глубину 200 уровнями. `JsonError` содержит смещение в байтах и строку/столбец от 1. Обратный вызов прогресса выполняется в потоке разбора; `json_load` показывает передачу результата через `std::future` и обновление UI в `idle()`.

CSV поддерживает кавычки, удвоенные кавычки, разделители внутри полей, многострочные поля и CRLF. Это формат данных: интерпретацию формул при открытии экспорта в электронных таблицах определяет принимающее приложение.

## Остальные виджеты

Дерево хранит `shared_ptr<TreeNode>`. Поле `loader` загружает детей при первом раскрытии ленивого узла; ошибка доступна через `error()`. После ручного изменения узлов вызывайте `refresh()`. Стрелки управляют раскрытием и курсором, Space переключает флажок, текст выполняет поиск. Циклические ссылки и чрезмерная глубина не приводят к бесконечному обходу.

`TProgressBar::setRange/setValue/step` ограничивают значение диапазоном и обрабатывают переполнение. Шаблоны подписи: `{percent}`, `{value}`, `{min}`, `{max}`. Для `indeterminate=true` приложение вызывает `pulse()` из таймера или `idle()`; виджет не создаёт потоков.

`TInputLong` передаёт `int64_t` через `getData/setData`, `TColor256Selector` — один `unsigned char`, `TTable` — номер строки `uint64_t`. Для `TCombo` действует строковый формат `TInputLine`; F4/Alt+Down открывает список, стрелки меняют элемент. Все размеры необходимо учитывать при формировании общей записи диалога.

Файловая модель использует Windows Unicode API и POSIX API на Unix. Фильтр `*`/`?` работает с UTF-8, регистронезависимое сравнение гарантировано для ASCII. Папки остаются видимыми при фильтрации. Ошибка чтения нового каталога сохраняет прежний список. Enter открывает каталог или передаёт `cmFileOpen`, Backspace поднимает на уровень, Insert отмечает файл. `newTab/selectTab/closeTab` управляют вкладками; `TDualPanel` переключается клавишей Tab. Методы фильтрации и отметок доступны через `panel.files()`.

Владение виджетами соответствует Turbo Vision: после `insert` ими управляет группа, которая должна пройти `shutDown()` перед удалением. Не изменяйте виджеты из фоновых потоков.
