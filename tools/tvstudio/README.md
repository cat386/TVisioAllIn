# TV Studio C++

Текстовая IDE и визуальный конструктор приложений C++ на TVisioAllIn, созданные по мотивам [cat386/tvstudio](https://github.com/cat386/tvstudio). В исходной ссылке `tvsudio` пропущена буква `t`.

## Сборка и запуск

Требуются CMake 3.16+, компилятор C++17 (GCC 9+, современный Clang или MSVC) и потоки ОС. Дополнительные библиотеки не нужны. Сама TVisioAllIn сохраняет совместимость с C++14; старый GCC 5 собирает библиотеку без инструментов.

Из корня репозитория:

```sh
cmake -S . -B build -DTV_BUILD_TOOLS=ON -DTV_BUILD_TESTS=ON
cmake --build build --config Release --parallel
```

Ninja/Make: `build/tvstudio`; Windows MSVC: `build/Release/tvstudio.exe`. В Windows MinGW это `build/tvstudio.exe`. Запускайте в UTF-8 терминале; рекомендуется размер от 100×30. Также можно собрать отдельно: `cmake -S tools/tvstudio -B build-studio`.

```sh
tvstudio
tvstudio /path/project/project.tvsp
tvstudio /path/existing-cmake-project
tvstudio --new my_app /path/empty-directory /path/TVisioAllIn
tvstudio --generate /path/project/project.tvsp
tvstudio --check /path/project/project.tvsp
tvstudio --import /path/sources /path/empty-directory imported /path/TVisioAllIn
tvstudio --smoke
```

Для сборки созданного проекта используйте меню «Сборка» либо обычные `cmake -S PROJECT -B PROJECT/build` и `cmake --build PROJECT/build --config Debug`. При переносе проекта исправьте `tvision_path` в `.tvsp` и повторите генерацию. Относительный путь отсчитывается от каталога проекта. Собранная IDE по умолчанию знает исходный каталог своей TVisioAllIn; для другой копии укажите путь при создании проекта.

## Возможности

* Проекты `.tvsp`, формы `.tvf` в YAML или JSON; чтение и сохранение неизвестных полей форм и компонентов.
* 14 компонентов: текст, метка, кнопка, строка ввода, флажки, переключатели, список, memo, combo, прокрутка, progress, таблица, дерево, линия.
* Визуальный дизайнер с настоящими виджетами, выбором мышью, несколькими выбранными элементами, переносом, изменением размеров, копированием, отменой/повтором, выравниванием и Tab-порядком.
* Инспектор показывает свойства выбранного элемента. Полное редактирование свойств, меню, команд и строки состояния выполняется в многострочном YAML-редакторе с проверкой результата.
* Предпросмотр диалогов и окон; чтение введённых данных, в том числе содержимого таблиц, в JSON.
* Генерация C++17/CMake: отдельные `Data` и `View`, функции `build/open/run`, команды, меню, статус, стартовая форма. `main.cpp` создаётся один раз. Файлы генератора помечаются; пользовательские файлы не перезаписываются.
* Несколько редакторов исходников: UTF-8, простая подсветка C++, многошаговая отмена, поиск, замена всех вхождений, переход к строке, clipboard, дополнение словами из буфера.
* CMake configure/build/run/test/clean, фоновый вывод, остановка группы дочерних процессов, разбор сообщений GCC/Clang/MSVC, переход к ошибкам. Команды запускаются через аргументы процесса без shell.
* clangd: дополнение, определение, использования, диагностика. Сервер запускается автоматически при открытии C/C++-файла; изменённые буферы передаются не чаще одного раза в 350 мс, без сохранения на диск. Закрытие и повторное открытие синхронизируются с сервером; одинаковые тексты повторно не отправляются. Координаты UTF-8/UTF-16 согласуются с сервером. Сборка создаёт `compile_commands.json` для поддерживающих его генераторов; дополнительно генерируется `compile_flags.txt`.

clangd устанавливается отдельно. В Windows программа ищет его в `PATH`, затем в стандартных каталогах LLVM и MSYS2 (clang64/ucrt64/mingw64). В Unix используется `PATH`. Путь и аргументы можно изменить через **Проект → clangd: команда запуска**; подтверждение перезапускает сервер. Ошибки запуска и сообщения сервера видны в панели сообщений; редактор остаётся доступен без clangd. Для подробного журнала добавьте `--log=verbose`. Настройка сборки и базы команд описана в [документации clangd](https://clangd.llvm.org/installation#project-setup).

Проверка с настоящим сервером: соберите с `TV_BUILD_TESTS=ON`, затем запустите `tvstudio-clangd-test "C:/msys64/mingw64/bin/clangd.exe"` (Unix: `./tvstudio-clangd-test clangd`). Тест проверяет ошибки в несохранённом буфере, их исчезновение после исправления, определение, дополнение и повторное открытие документа.
* Gruvbox по умолчанию, переключение Classic/Twilight в меню «Окна» с немедленной перерисовкой.

## Управление

При открытии проекта редактор автоматически показывает исходники из `open_files` (по умолчанию `src/main.cpp`). Без проекта открывается пустой буфер. F4 возвращает редактор кода, Shift+F4 — дизайнер. Двойной щелчок по исходнику в дереве открывает его; Ctrl+N создаёт новый буфер, F2 сохраняет его с запросом имени. Курсор нового открытого файла находится в начале. Сохранение всего проекта запоминает открытые исходники внутри его каталога.

| Клавиши | Действие |
| --- | --- |
| F1 / F2 / Ctrl+S | Помощь / сохранить / сохранить всё |
| F3, Enter | Дерево проекта, открыть выбранный файл или форму |
| F4 / Shift+F4 / Ctrl+N | Редактор кода / дизайнер / новый исходник |
| Insert / Enter в дизайнере | Добавить компонент / свойства |
| Щелчок / Ctrl+щелчок | Выбор одного / нескольких компонентов |
| Перетаскивание / Shift+перетаскивание | Перемещение / размер |
| Стрелки / Shift+стрелки | Перемещение / размер на одну ячейку |
| Delete, Ctrl+C/X/V/Z | Удалить, копировать, вырезать, вставить, отменить |
| F9 | Предпросмотр формы |
| Ctrl+F/R/G | Поиск / замена / номер строки |
| Ctrl+Space / F12 | Дополнение / определение через clangd |
| F7 / Ctrl+F9 / Ctrl+F2 / F8 | Сборка / сборка и запуск / остановка / следующая ошибка |
| F6 / Alt+X | Следующее окно / выход |

Закрытие редактора предлагает сохранить изменения; повторное открытие возвращает его буфер. Закрытие дизайнера скрывает окно, сохраняя историю. Предпросмотр выводит принятые данные в окно сообщений. Диалоги свойств поддерживают обычные команды редактирования TVisioAllIn.

## Формат и данные

Смотрите [пример «Контакты»](examples/contacts). Скопируйте его в рабочий каталог **вне исходного примера**, укажите `tvision_path` в `contacts.tvsp`, затем запустите `tvstudio --generate COPY/contacts.tvsp` и соберите полученный проект. Пользовательский `src/main.cpp` сохраняет карточку в `contact.json`, а при следующем запуске читает её обратно. Таблица, флажки, memo и combo участвуют в сериализации.

Основные поля формы: `name`, `title`, `class: Dialog|Window`, `x/y/w/h`, `centered`, `palette: gray|blue|cyan`, `number`, `resizable`, `help_ctx`, `controls`. Компонент имеет `kind`, уникальное C++-имя `name`, геометрию, `text` и поля своего типа. `items` таблицы — строки `Заголовок:ширина`, `text` — строки с ячейками через `|`; `items` дерева — строки с отступом в два пробела. Валидаторы ввода: `picture:...`, `range:MIN..MAX`, `filter:...`, `lookup:a|b`.

В `app.commands` задаются `name`, `value` (100–28671), `action` (`form:NAME`, `message:TEXT` или пустая пользовательская обработка), `comment`. В `app.menu` вложенные `items`, `title`, `command`, `key`, `separator`; в `app.status` — `text`, `key`, `command`. Коды стандартных команд пишутся `cm::OK`, `cm::CANCEL`, `cm::QUIT` и т. п.

Сгенерированные формы доступны через `forms::NAME::Data` и `forms::NAME::View`. Пример:

```cpp
forms::contact::Data data;
if (forms::contact::run(app, data) == cmOK) {
    // data.full_name, data.category, data.flags, data.phones, data.notes
}
```

Поля `build`: `cmake`, `generator`, `compiler`, `profile`, `target`, `extra`, `run_args`, `executable`, `jobs`. Для существующего CMake-проекта задайте `target` и, при необходимости, `executable`. Путь исполняемого файла может быть абсолютным либо относительно проекта. `extra` и `run_args` разбираются как аргументы с кавычками, не как shell-скрипт. Команда LSP хранится в верхнем поле `clangd`, например `"C:/LLVM/bin/clangd.exe" --clang-tidy`.

## Отличия от Rust TV Studio

Это самостоятельная реализация для C++/CMake. Cargo, Rust-кодогенерация, интерпретация Rust-исходников и Cargo workspace не переносятся. Импорт существующего C++/CMake копирует исходники и открывает проект; он не восстанавливает формы из произвольного C++-кода.

YAML поддерживает используемые моделями вложенные словари/списки, строки в кавычках, flow-коллекции, комментарии и блоки `|`/`>`. Якоря, aliases и пользовательские tags не поддерживаются; TOML не поддерживается. Совместимость моделей проверяется для перечисленных полей, побайтовая совместимость со всеми версиями Rust TV Studio не заявляется.

Свойства редактируются через YAML, а не через полный набор специализированных диалогов Rust-версии. Пока нет rubber-band выбора, LSP hover/quick-fix/rename, автопар скобок, полного лексера C++, поиска по всем файлам, recent-projects и постоянных общих настроек. CTest запускает тесты вашего CMake-проекта, если они в нём объявлены.

Тесты моделей, генератора, Unicode-путей, процессов, отмены, LSP и всех видов компонентов запускаются при сборке с `TV_BUILD_TESTS=ON`; `tvstudio --smoke` дополнительно проверяет пересоздание дизайнера и отмену в редакторе.
